PLUGIN INTERCEPTION AUDIT - 2026-09-26
========================================

METHOD NOTE (revised)
---------------------
An earlier revision recorded branch-protector as failing on the strength of a
Node unit harness. That harness was itself defective: it stubbed currentBranch
by capturing BRANCH when the stub was created, so every "should block" case
reported "allowed". The harness result was discarded, not acted on.

The verdict below rests on (a) a live Cline session and (b) a corrected
harness that runs the ORIGINAL and PATCHED logic side by side.
Original 8/18, patched 18/18. No production code was changed to satisfy a test.


env-blocker    PASS  (live session, both directions)
  - .env          -> tool output was
                     "Blocked read_files: reading environment secret files"
                     (beforeTool fired; the read never executed)
  - .env.example  -> ALLOWED, content returned. No over-blocking.


branch-protector  PATCHED AND VERIFIED LIVE

  ORIGINAL (official)  8/18 in the corrected harness. Two defects:
    1. reads toolCall.input.command (string); the runtime sends
       toolCall.input.commands (string[]). "if (!command) return" therefore
       exited on every real call. Confirmed live before the patch: a
       "git push origin master" on master reached git unblocked.
    2. /^\s*git\s+push\b/ is anchored, so "cd x && git push" never matched.
    env-blocker does not share defect 1; it reads command ?? commands ?? cmd.

  PATCH: extract command|commands|cmd and test each; split the line on
  && || ; newline | and test every segment. The guarded branch is the one
  checked out, not a refspec from the command, so a crafted refspec cannot
  smuggle a push through.

  A third defect appeared only in the live run and is now fixed:
    context is not always supplied; context.cwd threw
    "Cannot read properties of undefined (reading 'cwd')" and aborted the
    task. Now: context?.cwd ?? process.cwd().

  LIVE RUNTIME RESULTS (real Cline sessions, disposable repo, fake remote)
    git push origin master        -> BLOCKED   (after the cwd fix)
    git push origin main          -> BLOCKED
    git push origin release/test  -> BLOCKED   (glob works)
    git push origin feature/test  -> ALLOWED   (no over-blocking)
    cd bptest && git push origin master -> BLOCKED  (chain fix confirmed)
    git push --force-allow origin master -> reached git (bypass works)

  Note: on the first master attempt Cline declined on its own, citing the
  global isolation.md rule, and never issued a tool call. That is the
  secondary guard, not the plugin. The later runs forced a tool call so the
  beforeTool hook was genuinely exercised.

  Installed: 3,343 B. Original preserved at
  D:\rollback\branch-protector-ORIGINAL-index.ts (1,527 B, sha256 verified
  identical to the file before the patch). If a future Cline update replaces
  the plugin, compare against that backup.
